# 관측 결정 기록

관측 계층의 결정을 번호로 고정한다. 코드 주석과 설정 파일이 이 번호를 인용하므로, **여기
정의되지 않은 번호는 인용할 수 없다** — `ObservationDocReferenceTest` 가 그것을 강제한다.
근거 문서 없이 번호만 적으면 읽는 사람이 찾아갈 곳이 없다.

각 항목은 무엇을 정했는지, 왜 그렇게 정했는지, **그 결정이 만드는 반대 방향 실패**가 무엇인지
적는다. 마지막 것이 없으면 다음 사람이 그 대가를 모르고 결정을 되돌린다.

---

## DEC-04 — live 화면 버퍼에 결과 코드별 층화 샘플링을 건다

**정한 것** — Kafka `attempt-live` 컨슈머가 Redis Stream `attempt:live` 에 쓰기 전에, 결과
코드별 최소 표본을 보장하고 전체 초당 한도를 거는 샘플러를 통과시킨다. 손잡이는 셋이다
(`observation.attempt.live.sampling.*`). 구현은 `StratifiedSampler`, 계약은
`AttemptSamplingProperties`.

**왜** — 버퍼가 `MAXLEN ~ 200` 이다. 초당 attempt 가 3,000 건이면 200 개 버퍼는 **67ms
분량**이고 화면은 1 초마다 폴링한다. 샘플링이 없으면 매 폴링이 직전 67ms 창만 보는데, 그 창은
결과 코드에 대해 균등하지 않다 — 재고가 소진되면 거의 전부가 409 라, 그때 봐야 하는 5xx
한 건이 그 사이에서 사라진다. 샘플링은 화면을 줄이려는 것이 아니라 **드문 결과를 보이게**
하려는 것이다.

**통과 조건은 논리합이다.**

```
통과 = (층 카운터 < 층별 최소 보장)  또는  (전체 카운터 < 전체 상한)
```

왼쪽 항이 전체 상한을 보지 않는 것이 핵심이다. 흔한 결과가 상한을 다 써도 새 층은 왼쪽
항으로 들어온다.

**층은 `(eventType, httpStatus)` 다.** `reasonCode` 가 아니다 — 그것은 4xx·5xx 에만 있어
성공과 단계 이벤트를 층으로 가르지 못한다.

**반대 방향 실패**

| 대가 | 내용 |
|---|---|
| 전체 상한이 하드가 아니다 | 활성 층이 N 개면 실제 상한은 `max(전체 상한, N × 층별 최소)` 다. 늦게 나타난 층(= 새로 생긴 장애)이 그 초에 한 건도 못 들어가는 것보다 낫다고 판단했다. 실제 통과량은 `app_attempt_live_sampled_total` 이 낸다 |
| 인스턴스당이다 | 샘플러는 인스턴스 하나에 하나이고 리스너 스레드 셋이 공유한다. api 가 4 대면 Redis 쓰기는 최대 4 배다. 분산 한도를 두려면 Redis 를 한 번 더 왕복해야 해서 두지 않았다 |
| 창 경계에서 2 배까지 튄다 | 슬라이딩 창이 아니라 1 초마다 통째로 리셋한다. 화면이 1 초 폴링이라 그 편차가 관측되지 않고, 건별 타임스탬프 큐를 유지할 이유가 없다 |
| 층 상한을 넘은 층은 최소 보장이 없다 | 상태 코드가 예상 밖으로 퍼지면 층 수 × 최소 보장이 곱해져 전체 상한이 아무것도 뜻하지 않게 된다. 넘은 층은 전체 상한만 적용받는다 |

**수치는 아직 잠정값이다.** 이 결정이 고정하는 것은 손잡이의 이름과 의미이고, 값은 부하
배포 전에 실측으로 정한다. 값이 정해질 때 코드를 고쳐야 하면 그 회차에 코드 변경과 튜닝이
섞여 어느 쪽이 결과를 바꿨는지 못 가른다.

## DEC-10 — 매핑되지 않은 `ReasonCode` 는 유실이 아니라 `UNMAPPED` 다

**정한 것** — 매핑이 없는 `ErrorCode` 로 실패했을 때 이벤트를 버리지 않는다.
`ReasonCode.UNMAPPED` 로 발행하고 그 비율을 지표로 낸다.

**왜** — 매핑이 없다는 것은 **새 오류가 방금 배포됐다**는 뜻인 경우가 대부분이다. 그 순간이
정확히 관제가 가장 필요한 때인데, 매핑 부재를 유실로 처리하면 그때 화면에서 그 실패가 통째로
사라진다. "안 보이는 것" 과 "없는 것" 이 같은 모양이 된다.

**반대 방향 실패** — 매핑을 안 해도 아무 일이 안 일어나므로 `UNMAPPED` 가 방치된다. 그러면
실패 원인 표가 `UNMAPPED` 한 줄로 수렴해 아무것도 못 가른다. 그래서 비율 임계 경보를 함께
둔다 — 이 결정은 그 경보와 한 쌍이고, 경보 없이 이 결정만 가져가면 안 된다.

`UNMAPPED` 는 `OverviewPrometheusContract.isFailure` 에서 **서버 실패**로 분류된다. 정책
거절이 아니라 우리가 아직 모르는 실패라서다.
