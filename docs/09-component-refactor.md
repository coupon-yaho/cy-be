# 컴포넌트 구조 리팩토링

> `08-design-refactor.md` 는 **표면**(크기·굵기·간격) 이었다. 이 문서는 **구조** 다.
> 08 은 찾아 바꾸기로 끝나지만, 이건 컴포넌트를 쪼개고 합치는 작업이다.

---

## 0. 한 줄 요약

**같은 것이 네 벌 있고, 하나가 스물다섯 가지를 한다.**

```
쿠폰 카드   4 종   ← 화면마다 다르게 생겼다
달력        2 종   ← 같은 정보를 두 방식으로
패널 껍데기 14 회  ← 컴포넌트 없이 손으로 반복
CouponCard  25 요소 / 25 props  ← 그중 3개는 한 번도 안 그려진다
```

**그리고 아예 안 쓰이는 게 있다.**

```
A1 캠페인 생성 폼    입력 6 · 버튼 2 · 핸들러 0    화면 폭의 25%가 죽어 있다
재고 게이지          같은 숫자를 3가지로 반복
카테고리             아이콘 + 텍스트 칩으로 2번
U3 사이드바 로고     정보량 0
```

## 1. 쿠폰 카드가 네 벌이다

**같은 물건(쿠폰)이 화면마다 다르게 생겼다.** 사용자는 "아까 그 쿠폰이 이거 맞나?" 를 매번 다시 확인해야 한다.

| # | 어디 | 무엇 | 생김새 |
|---|---|---|---|
| **①** | `CouponCard.dc.html` | 정식 컴포넌트 | 레일 + 노치 + 점선 + 게이지 |
| **②** | U3 쿠폰함 `boxCoupons` | 손으로 만든 `<article>` | **리본 + USED 스탬프 + 접힌 모서리** + 펼침 바코드 |
| **③** | U3 브랜드별 가로 스크롤 | 또 다른 손 카드 | 값 + 상태칩 + 제목 + 만료 |
| **④** | 중복 발급 모달 안 | 미니 쿠폰 | 노치 2개를 **또 직접 그림** |

### ★ 제일 큰 문제 — 쿠폰함이 쿠폰 컴포넌트를 안 쓴다

`CouponCard` 를 호출하는 곳은 **U1 두 군데뿐**이다 (`215줄`, `355줄`).

**화면 이름이 "내 쿠폰함"인 U3 가 정작 그 컴포넌트를 안 쓴다.** 대신 리본·스탬프·접힌 모서리가 달린 완전히 다른 카드를 손으로 만들었다.

그래서 이런 일이 생긴다.

```
U1 에서 받은 쿠폰          U3 에서 보는 같은 쿠폰
┌─────────────┐          ┌─────────────┐
│▌ ☕ 모카빈    │          │  카페/디저트 ☕│   ← 배치가 반대
│ 아메리카노 무료│          │  아메리카노 무료│
│ ▓▓▓░ 6,412장 │          │  40%      D-6│   ← 게이지 → 값+D-day
├ · · · · · · ┤          │         [리본]│   ← 노치·점선 없음
│ 사용 08.12~18│          └───────────┘
│ [쿠폰 받기]   │
└─────────────┘
```

**노치도 점선도 좌측 레일도 U3 엔 없다.** 우리가 "쿠폰답게 보이려고" 만든 요소가 정작 쿠폰함에서 사라진다.

## 2. `CouponCard` 하나가 25가지를 한다

컴포넌트가 렌더하는 요소를 세어봤다.

```
 1 좌측 레일          10 남은 장수         19 이용 조건 목록
 2 오픈 시각 칩       11 게이지 바         20 쿠폰 코드 라벨
 3 상태 배지          12 전체 장수         21 쿠폰 코드
 4 카테고리 아이콘    13 % 남음            22 바코드 20줄
 5 브랜드명           14 노치 좌           23 액션 버튼
 6 카테고리 칩        15 노치 우           24 USED 스탬프
 7 혜택 제목          16 점선 절취선       25 잠금 오버레이
 8 혜택 설명          17 사용 기간 라벨
 9 "남은 수량" 라벨   18 발급 마감
```

**364 × 452px 안에 25개다.** props 도 25개다.

### 항상 꺼져 있는 기능이 5개

호출부(`215줄`·`355줄`)가 넘기는 속성을 대조했다.

| prop | 넘기는가 |
|---|---|
| `code` | **안 넘김** → 쿠폰 코드·바코드 22줄이 **한 번도 안 그려진다** |
| `stamp` | **안 넘김** → USED 스탬프가 **죽어 있다** |
| `compact` | **안 넘김** |

**코드·바코드·스탬프는 U3 를 위해 만들어졌는데, U3 가 이 컴포넌트를 안 쓴다.** 그래서 영영 실행되지 않는 코드다.

### 게이지와 코드는 같이 필요한 적이 없다

| 상황 | 필요한 것 | 필요 없는 것 |
|---|---|---|
| **아직 안 받음** | 재고 게이지 · 오픈 시각 · 받기 버튼 | 코드 · 바코드 · 스탬프 |
| **받아서 갖고 있음** | 코드 · 바코드 · 만료일 · 사용 버튼 | **재고 게이지** · 오픈 시각 · 발급 마감 |
| **다 씀** | 스탬프 · 사용일 | 게이지 · 코드 · 버튼 |

**재고는 내가 못 받았을 때만 의미가 있다.** 이미 받았으면 남은 수량은 남의 일이다.

그런데 한 컴포넌트가 둘 다 들고 있으니 **쓸 때마다 절반을 꺼야 한다.** 그게 props 25개의 정체다.

## 3. 처방 — 쿠폰 카드를 셋으로

### 3-1. 껍데기와 내용을 분리한다

```
CouponShell          쿠폰처럼 보이게 하는 것만
  · 좌측 레일 (brand.color)
  · 노치 좌우
  · 점선 절취선
  · 상단 / 하단 슬롯 두 개
     ↓ 이 껍데기를 아래 둘이 공유한다

CouponOffer          아직 안 받은 쿠폰        ← U1 · U2
  상단   오픈 시각 · 상태 · 브랜드 · 혜택
  하단   재고 게이지 · [받기] 버튼

CouponWallet         이미 받은 쿠폰          ← U3 · 모달
  상단   브랜드 · 혜택 · 만료 D-day
  하단   코드 · 바코드 · [사용하기] · USED 스탬프
```

**props 가 25개에서 8~10개로 줄어든다.** 그리고 U3 가 드디어 노치와 점선을 갖는다.

### 3-2. 이용 조건은 카드에서 뺀다

`terms[]` 2줄이 364px 카드 하단을 먹고 있는데, **카드 훑는 단계에서 이용 조건을 읽는 사람은 없다.**

```
카드          혜택 · 재고 · 버튼까지만
클릭 →        상세 시트에서 terms · 사용 기간 · 제외 매장
```

U3 가 이미 **클릭하면 펼쳐지는 방식**(`c.toggle` / `c.open`)을 쓰고 있다. **그 패턴을 U1 카드에도 쓰면 된다.**

### 3-3. 크기 변형은 prop 이 아니라 별도 쓰임으로

`compact` 불리언 대신 `size` 하나로.

```
size = "sm"   가로 스크롤 · 모달 안        (U3 브랜드별 · 중복 모달)
       "md"   그리드 기본                  (U1 3열 · U3 2열)
```

**③번 카드(브랜드별 가로 스크롤)와 ④번(모달 미니 쿠폰)이 `size="sm"` 하나로 흡수된다.** 손으로 만든 카드 두 벌이 사라진다.

## 4. 달력이 두 벌이다

| | U2 브랜드데이 | U3 쿠폰함 하단 |
|---|---|---|
| 그리드 | `repeat(5, 1fr)` 주 단위 | `repeat(7, 1fr)` 35셀 |
| 표현 | 관통선 + 솟은 수요일 + 주간 브랜드 | 날짜에 색 점(dot) |
| 정보 | 브랜드데이 회차 | **같은 브랜드데이 회차** |

**같은 정보를 두 방식으로 그리고 있다.** 사용자가 U2 에서 익힌 읽는 법이 U3 에서 안 통한다.

### 처방 — U3 의 달력을 지운다

U3 하단 `브랜드별 쿠폰 발급일` 블록(`495~522줄`)을 통째로 삭제하고 한 줄로 대체한다.

```
┌────────────────────────────────────────┐
│ 8월 브랜드데이 일정          보러 가기 → │
└────────────────────────────────────────┘
```

**달력은 U2 가 담당한다.** 쿠폰함은 내가 가진 쿠폰을 보는 곳이지 일정표가 아니다.

> 굳이 남긴다면 **다음 회차 D-day 한 줄**만. 35칸 달력은 과하다.

## 5. 대시보드 패널 껍데기가 14번 반복된다

```html
<!-- 이게 14번 -->
<div style="background:#FFFFFF; border:1px solid #E3E8EF; border-radius:...; padding:...">
```

매번 `border-radius` 와 `padding` 이 조금씩 다르다. **08 문서의 "radius 13종"이 여기서 나온다.**

### 처방 — `Panel` 컴포넌트 하나

```
Panel
  title       패널 제목
  hint        제목 옆 회색 보조 문구
  badge       우상단 상태 배지 (선택)
  span        그리드에서 차지할 열 수
  dim         비활성 (v1 에서 Redis 패널처럼)
     ↓
  <slot> 내용 </slot>
```

**`dim` 이 특히 중요하다.** 07 브리프의 "버전마다 비활성화되는 패널" 을 지금은 화면마다 손으로 처리해야 하는데, 껍데기가 컴포넌트가 되면 **prop 하나**로 끝난다.

## 6. 필요 없는데 자리를 먹는 것

### 6-1. A1 캠페인 생성 폼이 통째로 죽어 있다 ★★

`590~624줄` — 오른쪽 `380px` 패널 전체다.

```
입력 필드      6 개   (브랜드 · 총 수량 · 할인율 · 오픈 · 마감 · 등급)
버튼           2 개   (예약 저장 · 취소)
핸들러         0 개   ← onChange 도 onClick 도 없다
```

**값이 전부 `value="모카빈"` 처럼 하드코딩돼 있고 아무 데도 연결돼 있지 않다.** 타이핑해도 안 바뀌고 저장을 눌러도 아무 일이 없다. 화면 폭의 25%가 작동하지 않는 장식이다.

게다가 **07 브리프의 A5(브랜드데이 일정 관리)와 역할이 겹친다.** A5 는 `nthWeek × dayOfWeek` 반복 일정을 다루고, 이 폼은 단발 캠페인을 다룬다 — 둘 다 있으면 운영자가 어느 걸 써야 할지 모른다.

**처방: 이 폼을 지우고 A5 로 대체한다.** 목록에는 `+ 캠페인 추가` 버튼만 두고, 누르면 모달로.

> 남긴다면 **최소한 동작은 하게** 해야 한다. 발표 중에 누가 눌러보면 바로 들킨다.

### 6-2. 재고 게이지가 같은 숫자를 세 번 말한다

`CouponCard` 게이지 블록이 요소 5개를 쓴다.

```
남은 수량            6,412장       ← ① 라벨 + 값
▓▓▓▓▓▓░░░░                        ← ② 같은 값을 막대로
전체 10,000장       64.1% 남음     ← ③ 같은 값을 비율로
```

**하나의 사실을 세 가지 형태로 반복한다.** 364px 카드에서 이 블록만 세로 60px 를 먹는다.

```
바꿀 것
6,412 / 10,000                     ← 한 줄
▓▓▓▓▓▓░░░░
```

`%` 는 막대가 이미 보여준다. `"남은 수량"` 라벨은 `/ 10,000` 이 있으면 자명하다. **U1 히어로에도 같은 중복이 있다** (`133~147줄` — `bigLeftStyle` + `totalText` + `pctText` + 게이지).

### 6-3. 카테고리를 아이콘과 텍스트로 두 번 말한다

```
☕  모카빈             카페/디저트     ← 아이콘과 칩이 같은 말
```

`ICONS` 4종을 카테고리에 1:1 로 붙인 게 결정 ⑤ 였다. **아이콘이 카테고리다.** 칩은 지우고, 아이콘에 `title` 속성만 남긴다.

카드 상단 한 줄이 통째로 비고, 그 자리를 혜택 제목이 쓸 수 있다.

### 6-4. 그 외 지울 것

| 어디 | 무엇 | 처방 |
|---|---|---|
| **U3 사이드바** | 로고 키비주얼 카드 (`430줄`) | 한 칸을 로고 이미지가 통째로 먹는데 **정보가 0**이다. **만료 임박 쿠폰** 또는 **다음 회차 D-day** 로 교체 |
| **헤더** | `JWT` 버튼 (`64줄`) | 사용자 화면에 개발자 도구가 상시 노출. **DEMO 패널로 이동** (08 문서 ①) |
| **`CouponCard`** | `spacerStyle` | `minHeight:2px` 짜리 빈 `div`. 아무 역할이 없다 |
| **`CouponCard`** | `visibility:hidden` 슬롯 | `slotLabel` 이 없어도 자리를 차지한다. 정렬 목적이면 유지, 아니면 조건부 렌더 |
| **대시보드 상단** | 컨트롤 3줄 | `기간`·`갱신주기`·`엔진` 이 세 줄로 쌓여 세로 100px 를 먹는다. 앞의 둘은 **생김새가 똑같아서 뭐가 뭔지 모른다** — 한 줄로 합치고 라벨을 붙여라 |
| **대시보드 상단** | `engineNote` + `engineLockNote` | 같은 줄에 회색 설명이 두 개. 하나로 |
| **U1** | `ENDED` 카드 6개 | 3열 × 2행 회색 덩어리. 한 줄 목록으로 (08 문서 ⑦) |

### 6-5. 패널 번호 표기가 섞여 있다

```
① ② ③ … ⑨ ⑩        원문자
11 · 12 · 13 … 19 ·   숫자 + 가운뎃점
```

**10번과 11번 사이에서 표기법이 바뀐다.** ⑪~⑳ 도 있는데 굳이 갈아탔다.

전부 `11 ·` 형태로 통일한다 — 원문자는 폰트에 따라 안 보이는 경우가 있고, 24패널까지 가면 어차피 부족하다.

### 6-6. 지우면 안 되는 것

혹시 몰라 명시한다. **아래는 정보가 없어 보여도 목적이 있다.**

| | 왜 남기나 |
|---|---|
| U3 빈 상태의 로고 200px | 빈 화면에 브랜드를 두는 건 맞다 |
| 소진 모달의 까비 | 나쁜 소식일수록 캐릭터가 완충한다 |
| D1 하단 마스킹 안내문 (`731줄`) | **개인정보 마스킹은 채점 항목이다.** 다만 상시 노출 말고 `ⓘ` 툴팁으로 |
| 17·18 패널의 비활성 처리 | v1 에서 Redis, v1·v2 에서 Kafka 를 끄는 건 **의도된 설계다** (07 5절) |

## 7. 적용 순서

**08(토큰) 을 먼저 하고 이걸 한다.** 순서가 반대면 쪼갠 컴포넌트에 다시 손대야 한다.

```
0  지우기부터                     ← 제일 싸다. 코드가 줄어든다
   0-1  A1 캠페인 생성 폼 (죽은 폼)
   0-2  게이지 중복 3→1
   0-3  카테고리 칩
   0-4  U3 사이드바 로고 카드
   0-5  헤더 JWT 버튼 → DEMO 패널로
   ↓
1  Panel 컴포넌트                 14곳 → 1곳
   ↓
2  CouponShell 분리               레일 · 노치 · 점선
   ↓
3  CouponOffer / CouponWallet     25 props → 8~10
   ↓
4  U3 쿠폰함을 CouponWallet 으로   손 카드 ② 제거
   ↓
5  size="sm" 로 ③ ④ 흡수          손 카드 2벌 더 제거
   ↓
6  U3 달력 삭제 → 링크 한 줄
   ↓
7  terms 를 상세 시트로
   ↓
8  패널 번호 표기 통일
```

**0번을 먼저 하는 이유** — 지우는 건 되돌리기 쉽고, 지우고 나면 남은 것의 구조가 잘 보인다. 쪼개기 전에 버릴 것을 버려야 두 번 안 만진다.
