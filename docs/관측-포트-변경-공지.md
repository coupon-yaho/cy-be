# [공지] 관리 포트·batch 업무 포트를 호스트에 열지 않습니다

CY-213 에서 `compose.yml` 을 고쳤습니다. **`.env` 는 각자 고쳐야 합니다.**

## 각자 할 일 ① — 루트 `application.yml` 이 gitignore 대상이 됐습니다

`compose.yml` 이 마운트하는 배포 설정입니다. 환경마다 값이 달라 `.env` 와 같은 방식으로
바뀌었습니다. 신규 클론이나 이미 파일이 없는 경우:

```bash
cp application.yml.example application.yml
```

이미 쓰던 `application.yml` 이 있으면 그대로 두면 됩니다. 다만 템플릿에서 두 가지가
바뀌었으니 확인하세요.

```diff
  # batch 프로파일
- server.port: ${BATCH_PORT:9090}
+ server.port: ${BATCH_PORT:9091}

  # 비밀번호 fallback 제거 — .env 가 빠지면 조용히 약한 비번으로 뜨지 말고 죽어야 한다
- password: ${DB_PASSWORD:app-password}
+ password: ${DB_PASSWORD}
```

## 각자 할 일 ② — `.env` 두 줄

```diff
- BATCH_PORT=9090
+ BATCH_PORT=9091
- BATCH_HOST_PORT=9091     # 삭제 (ports 가 없어져 안 쓰임)
```

`BATCH_PORT` 는 batch 모듈 설정과 계약 테스트가 정한 값이 9091입니다. 지금 `.env` 만 9090이라
`batch/application.yml.example` 의 기본값과 어긋나 있었습니다.

## 무엇이 바뀌나

| 포트 | 전 | 후 |
|---|---|---|
| api 8080 (업무) | 호스트 공개 | **그대로** |
| api 9090 (actuator) | 호스트 공개 | **비공개** |
| batch 9091 (verify 업무) | 호스트 공개 | **비공개** |
| batch 9092 (actuator) | 비공개 | 그대로 |
| mysql 3306 | 호스트 공개 | 그대로 |

## 확인 방법이 바뀝니다

```bash
# 전
curl localhost:9090/actuator/health

# 후 — 컨테이너 안에서
docker compose exec api wget -qO- localhost:9090/actuator/health
docker compose exec batch wget -qO- localhost:9092/actuator/prometheus
```

Prometheus 도 호스트에 안 열려 있습니다. PromQL 은 관제 API 를 통해 보거나, 급하면
`docker compose exec prometheus wget -qO- 'localhost:9090/api/v1/query?query=up'` 를 씁니다.

## 왜

actuator 에 인증이 없습니다 — 이 프로젝트는 Spring Security 를 도입하지 않았고, **포트를 안
여는 것이 유일한 방어**입니다. allowlist 의 `exclude: env,configprops,beans,heapdump` 한 줄이
지워지면 `/actuator/env` 가 DB 비밀번호를 그대로 뱉습니다(PRD R12 가 지목한 실제 구멍).

Docker 는 인터페이스를 안 적으면 `0.0.0.0` 에 바인딩합니다. `localhost` 만 열리는 게 아니라
같은 네트워크의 누구나 접근합니다.

batch 9091 은 이유가 하나 더 있습니다. verify 온디맨드 트리거가 무인증으로 붙어 있어서,
열어 두면 아무나 300만 행 검증 배치를 돌릴 수 있습니다. **부하 측정 중에 그러면 비교표
수치가 오염됩니다.**

## 안 바뀌는 것

- `infra/prometheus/prometheus.yml` — `api:9090` · `batch:9092` 를 내부 네트워크에서 그대로 긁습니다
- `.env` 의 `MANAGEMENT_PORT=9090` — 컨테이너 안에서 쓰는 값이라 그대로 둡니다
