# 11 · 관제에 V2 가 찍히게 하기

발급이 v2 로 돌아도 **관제가 그걸 V2 로 보지 못하면 Phase 1 의 측정은 전부 무의미하다.**
지금 코드에는 세 자리가 비어 있다. 셋 다 S2 밖이고 담당이 다르다.

| # | 무엇이 비었나 | 어디 | 담당 |
|---|---|---|---|
| ① | 이벤트의 `engineVersion` 이 **전역 설정값**이다 | `IssuanceObservationContextFactory` | S4 · S5 |
| ② | `ReasonCode` 에 v2 반환 코드에 대응할 값이 없다 | `ReasonCode` | S5 |
| ③ | 정합성 리더가 **Hash 를 못 읽는다** | `ConsistencyRawValueReader` | S3 · S7 |

## ① 스탬프의 출처가 "설정" 이면 안 된다

```java
// IssuanceObservationContextFactory — 지금
snapshot.engineVersion()   // RuntimeConfigSnapshot 의 전역값
```

v1/v2 전환은 **회차 단위 토글**이다(§4.3 · S4). 전역 설정이 `V2` 인데 어떤 회차가 아직
v1 로 돌면 **v1 요청이 V2 로 찍힌다.** 그 상태로 잰 처리량은 v2 의 수치가 아니다.

**스탬프는 "이 요청을 실제로 처리한 엔진" 이어야 한다.** 회차 토글을 판정한 그 자리가
결과를 관측 컨텍스트로 넘긴다. 설정을 다시 읽어 추측하지 않는다 — 토글이 요청 도중
바뀌면 판정과 스탬프가 갈린다.

**검증** — 같은 인스턴스에서 v1 회차와 v2 회차를 각각 한 번씩 태우고
`issue_attempts` 의 `engine_version` 이 회차별로 갈리는지 본다. 전역값 하나로 찍히면 실패다.

## ② `ReasonCode` 가 v2 를 표현하지 못한다

현재 12개 중 v2 의 `-6` `-7` `-8` `-9` `-10` `-11` 에 대응할 값이 **하나도 없다.**

| Lua | 지금 뭉개지는 곳 | 필요한 것 |
|---|---|---|
| `-6` REPLAY_DONE | `ALREADY_ISSUED` 로 뭉개면 **멱등이 고장으로 보인다** | 별도 값 |
| `-7` REPLAY_PENDING | `UNMAPPED` | 별도 값 |
| `-8` 값 파손 | `INTERNAL_ERROR` | 별도 값(재고 증발 신호다) |
| `-9` 게이트 미준비 | `TEMPORARILY_UNAVAILABLE` | 별도 값(재구성 창인지 아닌지가 다르다) |
| `-10` 인자 이상 | `INTERNAL_ERROR` | 별도 값(호출부 버그) |
| `-11` 카운터를 못 읽음 | `INTERNAL_ERROR` | 별도 값. `-9` 와 **대응이 다르다** — 기다려서 풀리지 않는다 |

`-1` `-2` `-3` `-4` `-5` 는 기존 값에 그대로 붙는다 —
`CAMPAIGN_CLOSED` · `NOT_OPENED` · `GRADE_NOT_ELIGIBLE` · `ALREADY_ISSUED` · `STOCK_EXHAUSTED`.

**뭉개면 04 의 카운터 분리가 무너진다.** `-4` 와 `-6` 을 같은 이유 코드로 내보내는 순간
`dupPerMember` 급증이 재시도에 묻힌다 — 04 가 응답에서 막은 것을 관제에서 되돌리는 셈이다.
`UNMAPPED` 로 떨어지는 v2 경로가 하나라도 있으면 S5 는 안 끝난 것이다.

## ③ 정합성 리더가 v2 의 `issued` 를 고장으로 읽는다

```lua
-- ConsistencyRawValueReader 의 size()
if t == 'set'    then SCARD
elseif t == 'zset' then ZCARD
elseif t == 'list' then LLEN
elseif t == 'string' then GET
elseif t == 'none' then false          -- 예열
else 'INVALID_TYPE' end                -- 고장
```

**`hash` 분기가 없다.** v2 의 `cy:v2:issued:{r}` 는 Hash 이므로 `INVALID_TYPE` →
`SourceStatus.UNAVAILABLE` 로 떨어진다. 바로 위 javadoc 이 "회원 집합의 자료구조는
V2·V3 구현이 정하므로 여기서 못 박지 않는다" 고 해 놓고 hash 만 빠졌다.

`ConsistencyGapType.isApplicable` 은 **V2 에 4축을 전부 적용한다.** 축 하나가 영구
`UNAVAILABLE` 이면 **V2 는 FINAL 을 영원히 통과하지 못한다.** 09 의 완료 기준이
여기서 막힌다 — 발급을 아무리 잘 만들어도 끝나지 않는다.

- 키 **이름**은 `DomainGaugeProperties` 로 설정 가능하므로 문제가 아니다. **자료형 분기**가 문제다
- `HLEN` 은 O(1) 이라 §3.3 에 걸리지 않는다. `HGETALL`·`HKEYS` 로 세지 않는다
- 파손 field 도 `HLEN` 에 잡힌다. 그래서 05 의 `corruptFieldCount` 가 **`LUA_GAP` 해석의
  입력**이다 — 값이 0이 아니면 gap 의 일부는 파손이지 발급 누락이 아니다(회수는 13)

**S3 가 키를 확정하는 순간 같이 닫는다.** 어댑터가 키 이름을 정해 놓고 리더가 그 키를
못 읽으면, 그 사실은 부하 시험 끝에 FINAL 이 안 나올 때야 드러난다.

## 무엇이 언제 확인되나

| 시점 | 확인 |
|---|---|
| S3 완료 | 리더가 v2 키 3종을 읽어 `VALID` 를 낸다 (`UNAVAILABLE` 아님) |
| S4 완료 | 회차별 토글이 이벤트의 `engineVersion` 을 가른다 |
| S5 완료 | v2 경로에서 `UNMAPPED` 가 0 이고, 이상 카운터 **8종**이 전부 나온다. `counterUnreadable` 과 `stockMissing` 을 합치지 않는다 — **당직자의 점검 범위가 다르다** |
| S10 | 소규모 부하 후 **V2 로 gap 4축 전부 0** — ③이 안 닫히면 여기 도달 못 한다 |
