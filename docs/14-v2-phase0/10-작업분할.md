# 10 · 작업 분할

**티켓은 CY-646 하나다.** 아래 단위로 나눠 각각 독립 커밋한다.
다른 세션이 하나만 집어서 cold 로 시작할 수 있게 범위와 완료 조건을 닫아 두었다.

## 전제 — v2 발급 경로는 아직 없다

`EngineVersion.V2` 는 정합성·관측 축에만 쓰인다. 발급은 `CouponIssueService`(v1) 하나뿐이고
`infra/redis` 에도 발급 코드가 없다. **이 작업은 수정이 아니라 신규 구현이다.**

## 의존 그래프

```
S1 값 codec
 └ S2 Lua 5종
     └ S3 게이트 포트·어댑터
         ├ S4 발급 유스케이스 ─ S5 응답·지표 ─ S9 경합 테스트
         ├ S6 재고 복원 연결        (S4 와 병렬)
         ├ S7 PENDING 계측          (병렬)
         └ S8 재구성·재동기화 + 락   (병렬)
                                        └ S10 문서 정합·완료 확인
```

## 커밋

```
feat(CY-646): <한 줄>      ← S1~S8
test(CY-646): <한 줄>      ← S9
docs(CY-646): <한 줄>      ← S10
```

**단위 하나 = 커밋 하나.** 섞지 않는다. 되돌릴 때 이게 전부다.

## 병렬로 돌릴 때

S3 가 끝나면 S4 · S6 · S7 · S8 이 서로를 안 기다린다.
다만 **S4 와 S6 은 같은 core 모듈**이라 파일 충돌 가능성이 있다 — 먼저 잡는 쪽이 알린다.

## 발급 코드는 어디까지 재사용하나

`CouponIssueService`(v1) 를 **재활용하지 않는다.** v1 트랜잭션에는 재고 차감이 반드시
들어가야 하고 그것이 v1 의 정체성이다(§8.2). v2 는 재고 판정이 Redis 로 갔으므로 TX 에
남는 것은 INSERT 3개뿐이다.

```
재사용하는 것   IssuanceRepository · IssuanceHistoryRepository · IdempotencyRepository
새로 만드는 것  v2 발급 유스케이스(S4) · 게이트 포트와 어댑터(S3)
만들지 않는 것  IssuancePersister 같은 영속화 래퍼 (§4.7)
```

래퍼를 만들지 않는 이유는 §4.7 에 있다 — 트랜잭션 경계의 **실패 의미가 v2 와 v3 에서
다르다.** 시그니처를 미리 맞추면 v3 에서 갈아엎게 된다.

## 문서가 나뉜 이유

`12`(인자 가드)와 `13`(파손 회수)은 **02·03 에서 떼어낸 것**이다. 인자 규약은 5종이
공유하고, 회수는 호출 지점이 S8 하나뿐이라 완료·보상과 수명이 다르다.
**스크립트를 고치면서 `12` 를 안 고치면 표가 코드와 갈라진다** — S2 완료 조건에 넣었다.

S3 · S4 · S5 · S7 · S10 은 **11(관제 반영)이 자기 단위의 완료 조건에 들어 있다.**

## 다음 단위로 넘긴 부채

| 받는 단위 | 내용 |
|---|---|
| **S3** | `{r}` 해시태그를 강제하는 **v2 키 빌더**를 어댑터가 소유한다. 지금 키 리터럴은 S2 계약 테스트에만 있다(12) |
| **S3** | 5종의 **KEYS 순서가 제각각**이다 — `issued_ever` 가 선점에서는 `KEYS[4]`, 보상·회수에서는 `KEYS[3]`. 어댑터가 키 리스트를 잘못 넘기면 `readableCounters` 의 everKey 가 `meta` 가 되어 **모든 보상이 영구히 `-11`** 이다. 스크립트별 타입으로 가두거나 순서를 통일한다 |
| **S8** | `meta` 의 `openAt`·`closeAt`·`gradeMask` 에는 형식 가드가 없다(`totalQuantity` 만 있다). 작성 계약을 넓히려면 다섯 필드에 같은 `isCanonicalInt` 를 건다 — 초과 발급 방향은 아니라 급하지 않다 |
| **S6** | **단건 복원(취소·사용취소) 스크립트가 아직 없다.** `06` 의 "← 있다" 는 v1 경로다. `INCR stock` 한 줄로 때우면 상한 없는 복원 경로가 새로 생긴다 |
| **S8** | **재고 시딩 통로가 없다.** 포트에 `meta` 쓰기는 있는데 `stock`·`issued_ever` 를 처음 쓰는 연산이 없다. 선점은 `stock` 키 부재를 예열로 안 봐주고 `-11` 로 내므로 **`meta` 를 먼저 쓰면 그 창의 모든 요청이 오경보**다. 순서(3·4 → 5)는 07 의 절차가 지는 계약이라 S3 에서 `SET` 두 개를 얹지 않았다(12) |
| **S4 S6** | **Redis 통신 실패는 게이트 포트 밖으로 전파된다.** 명령 타임아웃(500~800ms)은 "실행되지 않았다" 가 아니다 — 서버는 스크립트를 완주하므로 선점이 성립한 채 호출부만 예외를 받고, 그 `P` 는 DB 에 짝이 없어 만료 배치로도 안 풀린다. **예외 경로에서 같은 요청토큰으로 보상을 부른다**(12) |
| **S7** | **관측 대상 회차·엔진의 출처가 기동 시 고정이다**(`DomainGaugeProperties`). 회차마다 batch 를 재시작해야 하고, 엔진만 V2 로 뒤집으면 Redis 키 넷이 v1 이름이라 리더가 **영구히 PENDING** 이다. 진행 중인 `benchmark_runs` 행에서 읽는다 — 코드의 `TODO(OBS-14b)` 자리이고 `BatchBenchmarkRunsAssumptionTest` 가 시점을 알려 준다. **S10 의 "V2 로 gap 4축 0" 이 사실상 이걸 요구한다** |
| **S7** | **V2 의 대기열 없음이 `N_A` 로 안 나온다.** 대기열은 v3 것인데 `queueStatusFor` 는 V1 만 `N_A` 로 두므로, V2 에서는 없는 키를 1초마다 조회해 **영구히 `PENDING`** 이다. 경보는 아니지만 화면이 계속 "준비 중" 으로 보인다. 빈 키로 끄는 것도 안 된다 — `DomainGaugeProperties` 가 blank 를 기본값(V1 키)으로 되돌린다 |
| **S5** | **관리자 경로가 무인증이다.** `/api/v1/admin/**`(런타임 설정 CAS 교체 · 벤치마크 시작)이 compose 에서 공개된 8080 에 있고, `Caller` 는 인증 결과가 아니라 자기신고 헤더다(`CallerFilter`). batch 의 9091 은 같은 이유로 아예 안 열어 뒀다 — **한쪽만 막혀 있다.** 관제에서 엔진을 클릭으로 전환할 거면 이게 그 앞이다 |

## 빌드 범위

전체 build 를 돌리지 않는다. **관여 모듈만.**
S1 core · S2 infra/redis(+core) · S3 infra/redis(+batch) · S4 S6 core · S5 api · S7 S8 batch.

S2 가 core 를 건드리는 이유는 하나다 — 요청토큰의 `isBlank()` 를 `isEmpty()` 로 낮춰
Lua 캡처 `([^|]+)` 와 판정을 맞춘 것(01). 그 외 core 변경은 S2 범위가 아니다.
