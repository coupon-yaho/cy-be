# 10 · 작업 분할

**티켓은 CY-646 하나다.** 아래 단위로 나눠 각각 독립 커밋한다.
다른 세션이 하나만 집어서 cold 로 시작할 수 있게 범위와 완료 조건을 닫아 두었다.

## 전제 — v2 발급 경로는 아직 없다

`EngineVersion.V2` 는 정합성·관측 축에만 쓰인다. 발급은 `CouponIssueService`(v1) 하나뿐이고
`infra/redis` 에도 발급 코드가 없다. **이 작업은 수정이 아니라 신규 구현이다.**

## 의존 그래프

```
S1 값 codec
 └ S2 Lua 5종
     └ S3 게이트 포트·어댑터
         ├ S4 발급 유스케이스 ─ S5 응답·지표 ─ S9 경합 테스트
         ├ S6 재고 복원 연결        (S4 와 병렬)
         ├ S7 PENDING 계측          (병렬)
         └ S8 재구성·재동기화 + 락   (병렬)
                                        └ S10 문서 정합·완료 확인
```

## 우선순위 — 프로토타입이 먼저다

**시간이 없다. 목표는 "v2 가 한 번 끝까지 돈다" 이지 "v2 가 완성된다" 가 아니다.**
아래 넷이 끝나면 v2 로 부하를 걸 수 있다. 나머지는 그 뒤에 리팩토링으로 붙인다.

위 표가 **전체 범위**이고 이 절은 그중 **먼저 할 것**을 고른다. 단위 번호는 그대로 두되
S8 만 둘로 쪼갠다 — **S8a**(워밍업) 와 **S8b**(그 외). 나눈 이유는 S8a 없이는 v2 가
한 번도 안 도는데 S8b 는 장애 대응이라 성격이 다르기 때문이다.

### 최소 경로 — 이것만 하면 v2 가 돈다

| 단위 | 어디까지 | 왜 못 미루나 |
|---|---|---|
| **S4** | 전부 | 발급 자체다 |
| **S5** | **반환 코드 → HTTP 매핑까지만.** 카운터는 3종(`dupPerMember`·`replayDone`·`replayPending`) | `-4`/`-6`/`-7` 을 뭉치면 멱등이 고장난 것이고 이건 **클라이언트 계약**이라 나중에 못 고친다 |
| **S8a** | **워밍업만** — DB 집계 → 세 키 쓰기 → `meta` 쓰기 | `meta` 가 없으면 Lua 가 `-9` 를 내서 발급이 전부 503 이다. 없으면 v2 가 한 번도 안 돈다 |
| **S9** | 전부 | 이 프로젝트의 헤드라인이 "초과 발급 0건" 이다. 증명 없이 돈다고 말할 수 없다 |

S7 은 이미 진행 중이라 최소 경로와 별개로 그대로 간다.

### 뒤로 미루는 것

| 단위 | 미루는 부분 | 미뤄도 되는 근거 | 언제까지 |
|---|---|---|---|
| **S5** | 이상 카운터 8종 | 진단용이라 나중에 붙여도 과거 데이터를 안 잃는다 | 측정 회차 전 |
| **S6** | 취소·사용취소·만료의 복원 연결 전부 | 측정 시나리오가 **발급 + 조회뿐**이라 취소가 안 들어온다. 만료 배치는 지난 회차를 만지므로 v2 회차와 행이 겹치지 않는다 | **실서비스 전에는 반드시.** 없으면 취소한 재고가 영영 안 돌아온다 |
| **S8b** | 4′ 재집계 · 동시 실행 락 · 파손 회수 호출 | 전부 장애 대응이다. 측정 중 Redis 가 죽으면 회차를 다시 만든다 | 운영 전 |
| **S10** | 문서 정합 | 마지막에 한 번 | 마지막 |

**미룬다 = 안 한다가 아니다.** 위 "언제까지" 열이 그 약속이다. 프로토타입이 돌기 시작하면
이 표를 다시 열어 남은 것을 티켓으로 나눈다.

### 범위에서 빠진 것 — 기록

| | 내용 | 왜 |
|---|---|---|
| 살아있는 회차 전환 | §4.3 의 "전환 시점에 §6.2 재구성을 한 번 태운다" 를 구현하지 않는다 | 회차 엔진은 **생성 시점에 정해지고 오픈 중에는 안 바뀐다**(오픈 전·마감 후 `UPDATE` 만 허용). 램프는 단계마다 새 회차를 쓰므로(§10.2) 진행 중 전환이 필요 없다. 만들면 S4 가 S8 을 기다리게 되어 병렬이 무너진다 |
| 가용성 장치 | AOF · replica · Sentinel | D4 가 "당장 대응 없음" 으로 확정. **프로토타입이 돈 뒤 D4 를 다시 연다** — 그때는 설계 결정이지 작업 분할 항목이 아니다 |

## 커밋

```
feat(CY-646): <한 줄>      ← S1~S8
test(CY-646): <한 줄>      ← S9
docs(CY-646): <한 줄>      ← S10
```

**단위 하나 = 커밋 하나.** 섞지 않는다. 되돌릴 때 이게 전부다.

## 병렬로 돌릴 때

S3 가 끝나면 S4 · S6 · S7 · S8 이 서로를 안 기다린다.
다만 **S4 와 S6 은 같은 core 모듈**이라 파일 충돌 가능성이 있다 — 먼저 잡는 쪽이 알린다.

## 발급 코드는 어디까지 재사용하나

`CouponIssueService`(v1) 를 **재활용하지 않는다.** v1 트랜잭션에는 재고 차감이 반드시
들어가야 하고 그것이 v1 의 정체성이다(§8.2). v2 는 재고 판정이 Redis 로 갔으므로 TX 에
남는 것은 INSERT 3개뿐이다.

```
재사용하는 것   IssuanceRepository · IssuanceHistoryRepository · IdempotencyRepository
새로 만드는 것  v2 발급 유스케이스(S4) · 게이트 포트와 어댑터(S3)
만들지 않는 것  IssuancePersister 같은 영속화 래퍼 (§4.7)
```

래퍼를 만들지 않는 이유는 §4.7 에 있다 — 트랜잭션 경계의 **실패 의미가 v2 와 v3 에서
다르다.** 시그니처를 미리 맞추면 v3 에서 갈아엎게 된다.

## 문서가 나뉜 이유

`12`(인자 가드)와 `13`(파손 회수)은 **02·03 에서 떼어낸 것**이다. 인자 규약은 5종이
공유하고, 회수는 호출 지점이 S8 하나뿐이라 완료·보상과 수명이 다르다.
**스크립트를 고치면서 `12` 를 안 고치면 표가 코드와 갈라진다** — S2 완료 조건에 넣었다.

| **S5** | **관리자 경로가 무인증이다.** `/api/v1/admin/**`(런타임 설정 CAS 교체 · 벤치마크 시작)이 compose 에서 공개된 8080 에 있고, `Caller` 는 인증 결과가 아니라 자기신고 헤더다(`CallerFilter`). batch 의 9091 은 같은 이유로 아예 안 열어 뒀다 — **한쪽만 막혀 있다.** 관제에서 엔진을 클릭으로 전환할 거면 이게 그 앞이다 |
| **S5** | **`__rebuilt__` 를 클라이언트가 보낼 수 있다.** 워밍업(S8a)이 `issued` 값의 멱등키 자리에 그 리터럴을 박는데, 거절하는 코드가 API 헤더에도 CLAIM 인자 가드에도 없다. 그 회차에 발급 이력이 있는 회원이 `Idempotency-Key: __rebuilt__` 로 요청하면 키가 일치해 `-6` 이 나가고, `V2CouponIssueService` 가 `idempotency_records` 에서 못 찾아 **확정 500** 이다. 재고는 안 새고 1인 1매도 안 깨지는 순수 가용성 결함이다. 문자열은 `docs/12` 에 공개돼 있어 추측할 필요도 없다. **마커를 바꾸는 것은 해법이 아니다** — 헤더 검증과 Lua 가드(`-10`) 두 겹이다. 앞 겹이 S5, 뒷 겹은 S2/S8b(스크립트를 고치면 `12` 의 표도 함께). **앞 겹은 새로 만들 것이 아니다** — `IdempotencyKeys.validate` 가 UUID v4 를 강제하고 v1 발급이 이미 그것을 부르는데(`CouponOperationExecutionService`), **v2 경로에는 그 호출이 없다.** `__rebuilt__` 는 그 정규식을 통과하지 못한다 |
| **S8b** | **회차의 누적 회원을 힙에 통째로 올린다.** 러너가 `List<RebuiltIssued>` 로 materialize 하고 어댑터가 인코딩 맵을 한 벌 더 만들어, 두 컬렉션이 동시에 산다. 상한도 스트리밍도 없다. 회차당 1만에서는 안 터지지만 **이 저장소가 스스로 한 회차 300만 행을 실측 전제로 적고 있다**(`ConsistencyRawValueReader`). 고치기 어려운 이유는 지금 구조가 `issued_ever = 목록.size()` 라 **I4(LUA_GAP)를 구조적으로 0 으로 만드는 유일한 장치**라는 것이다 — 스트리밍 세션으로 쪼개면 그 보장이 호출부 규약으로 내려온다. 상한 거절(`TOO_LARGE_ROUND`)은 조용한 OOM 을 명시적 거절로 바꿀 뿐 올리지는 못한다. **프로토타입 측정 범위 밖이라 미룬다** |

## 빌드 범위

전체 build 를 돌리지 않는다. **관여 모듈만.**
S1 core · S2 infra/redis(+core) · S3 infra/redis(+batch) · S4 S6 core · S5 api · S7 S8 batch.
