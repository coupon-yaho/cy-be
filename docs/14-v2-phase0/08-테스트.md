# 08 · 테스트

Phase 0 의 결함은 **두 개가 동시에 일어날 때만** 드러난다.
읽어서는 다시 못 잡으므로 테스트로 박는다.

## 기존 C1~C8 에 더한다

| # | 주입할 고장 | 방법 | 기대 |
|---|---|---|---|
| **C9** | 회수와 커밋의 인터리브 | 회수 로직을 강제 호출한 **직후** 원 요청 커밋 | 초과 발급 0. 완료 CAS 가 `-1` + `completeCasMiss` |
| **C10** | 보상된 field 에 DONE 승격 | 보상 실행 후 완료 CAS 호출 | field 가 **부활하지 않는다.** `-1` 반환 |
| **C11** | 배치 복원 상한 초과 | `stock + n > total` 이 되도록 만료 배치 주입 | `-2` + 경보. `stock` 불변. 그 회차 만료가 **멈춘다** |
| **C12** | 멱등키 접두 충돌 | 같은 회원, `stored=abcdef…` 에 `request=abc` | 발급 `-4`, 보상 `0` + 기존 선점 불변 |

## C12 기대값에 주의

접두 비교를 고치는 목적은 **그 요청을 통과시키는 것이 아니다.**
같은 회원이 이미 받았으면 어차피 거절이 맞다.
목적은 **서로 다른 키를 같은 키로 오인하지 않는 것**뿐이므로 결과는 여전히 `-4` 다.

## 인터리브를 결정론적으로 만드는 법

`Thread.sleep` 으로 타이밍을 맞추면 CI 에서 깨진다. **래치를 쓴다.**

```
테스트가 제어하는 지점
  ① INSERT 직전        — 여기서 멈추고 회수 로직을 부른다
  ② 커밋 직후·완료 CAS 직전 — 여기서 멈추고 보상을 부른다
```

- 프로덕션 코드에 훅이 생긴다. **테스트 프로파일에서만 활성**되게 한다
- hot path 에 분기가 남지 않게 컴파일 타임 또는 no-op 구현으로 분리한다

## codec 단위 테스트 (01)

- 인코딩 → 디코딩 round-trip. **멱등키에 `|` 포함**한 입력
- 앞 세 필드에 `|` 를 넣으려는 시도가 인코딩에서 거부되는지
- 접두가 겹치는 두 키가 서로 다르게 판정되는지
- 음수 선점 시각·빈 멱등키·빈 요청토큰이 값 객체 생성 시 거부되는지
- 공백뿐인 멱등키·요청토큰은 **거부되지 않는지**(Lua 와 같은 답이어야 한다)
- 서로 다른 기동의 생성기가 각 1,000개를 만들어도 교집합이 비어 있는지
- 멀티스레드에서 생성한 토큰에 중복이 없는지

파손 값이 `-8`/`-3` 으로 나오는지는 codec 밖이다 — 아래 Lua 계약 테스트에서 닫는다.

## Lua 계약 테스트 — S2 에서 닫았다

`IssuanceScriptContractTest`(infra/redis). 실제 Redis 에 태운다.
**CI 가 이 클래스를 이름으로 지정해 한 번 더 돌린다** — Docker 가 없으면 `@Testcontainers`
가 통째로 skip 하고 skip 은 green 이라, 그대로 두면 "계약 테스트 green" 이 공허하게 참이 된다.

- 선점 → 완료 → 재시도 = `-6`
- 선점 → 보상 → 재시도 = **새 선점 성공**(field 가 지워졌으므로)
- 선점 A → 보상을 **B 의 토큰**으로 시도 = `0`, 상태 불변
- 선점 → 완료를 **B 의 토큰**으로 시도 = `-2`, 상태 불변
- 배치 복원 `stock + n > total` = `-2`, `stock` 불변

**코드 번호만 보는 테이블은 아무것도 안 지킨다.** 거절이 재고·`issued_ever`·field 를 어떤
상태로 남기는지까지 본다 — 매진 롤백(`HDEL`)을 지웠을 때 빨강이 나오는지가 그 테스트의 기준이다.
`-1` `-2` `-3` `-5` `-9` `-10` 과 복원 `-1` `-3`, 파손 회수 3분기가 전부 실행돼야 한다.

## 경합 테스트 — 순차 테스트로는 증명되지 않는 것

스크립트 하나는 원자적이지만 **여러 클라이언트가 같은 키를 두드리는 것**은 별개다.
순차 테스트만 있으면 "원자성에 기대고 있다" 는 사실 자체가 검증되지 않는다.

| 케이스 | 기대 |
|---|---|
| 재고 5장에 20명 동시 선점 | 성공 정확히 5. `stock` 0. `issued_ever` 5. **field 수 5** |
| 같은 회원·같은 키로 12개 동시 | 성공 1 · `-7` 11. 재고 1장만 빠진다 |
| 완료 CAS 12개 동시 | `1` 한 번 · `0` 열한 번 |
| 보상과 배치 복원 동시 | `stock` 이 `total` 을 넘지 않는다 |

**field 수를 세는 이유** — 매진 롤백이 남의 field 를 지우면 성공 수는 맞는데 field 만 준다.
반환 코드만 보면 안 잡힌다.

**도달 가능 최대치가 단언과 같으면 그 테스트는 아무것도 안 지킨다.** 헤드룸이 2인데 복원을
2건만 쏘면 상한 검사를 지워도 초록이다 — **요청이 헤드룸을 반드시 넘게** 배치를 짠다.
확인법은 하나뿐이다: 지키려는 그 줄을 지우고 빨강이 나오는지 본다.

## Java·Lua 교차 판정 테이블

**같은 입력을 양쪽에 먹인다.** 한쪽만 통과하는 입력이 하나라도 남으면 `LUA_GAP` 이
0 으로 수렴하지 못한다. 근거와 규격은 `01-값-형식.md` 하단 "S1 에서 확정한 것".

| 입력 | 기대 | 왜 |
|---|---|---|
| `X\|1\|t\|k` | 양쪽 파손 | 상태 문자 `[PD]` 제한 |
| `P\|1\|t\|` | 양쪽 파손 | 빈 멱등키. Lua 캡처가 `(.*)` 면 Lua 만 정상이 된다 |
| `P\|1\|t\|   ` | 양쪽 정상 | 공백만 있는 키. Java 가 `isBlank()` 면 Java 만 파손 |
| `P\|1\|t\|order-1\ntrace-2` | 양쪽 정상 | 개행은 금지 문자가 아니다. Java 에 `DOTALL` 이 없으면 Java 만 파손 |
| `P\|12345678901234\|t\|k` | 양쪽 파손 | 14자리 = 경계 바로 밖. `Long` 은 멀쩡히 파싱하므로 자릿수로 걸러야 한다 |
| `P\|9999999999999\|t\|k` | 양쪽 정상 | 13자리 = 경계 안. 상한을 너무 좁게 잡는 실수를 잡는다 |
| `P\|1\|   \|k` | 양쪽 정상 | 공백뿐인 토큰. S2 가 core 를 건드린 유일한 이유(`isBlank`→`isEmpty`)를 지킨다 |
| `P\|1\|\|k` | 양쪽 파손 | 빈 요청토큰 |

**8행을 한 테이블에 모은다.** 개행 행만 따로 빼서 Lua 반환만 확인하면
`Pattern.DOTALL` 이 지워졌을 때 잡을 테스트가 저장소 어디에도 안 남는다.

토큰의 codec 계약은 "비어 있지 않다" 와 "`|` 가 없다" 둘뿐이고, 공백을 거부할 자리는 생성기다(01).

## 인코딩 방향도 대조한다

교차 테이블은 **디코딩 방향만** 본다. 그래서 Lua 가 쓴 값을 `startsWith` 로 확인하면
5번째 필드가 붙어도 통과하고, 그러면 Java codec 의 `(.+)$` 가 그걸 **멱등키로 흡수**해
`hasIdempotencyKey` 가 영구 false 가 된다 — 재시도가 전부 `-4` 로 떨어진다.

**선점·완료가 쓴 값은 `codec.encode(...)` 와 글자 하나까지 같아야 한다.**
승격은 **상태 한 글자만** 바뀌는지도 같이 본다 — 선점시각이 덮이면 빨강이어야 한다.

## S9 인계 — 래치가 필요한 것만 S9 다

Lua 는 스크립트 하나가 원자적이라 **스크립트 내부의 인터리브는 존재하지 않는다.**
C9·C10 이 재현하려는 것은 `Lua → DB → Lua` 사이의 창이므로 **S4 의 유스케이스가 있어야
쓸 수 있다.** S2 의 계약 테스트로는 못 닫는다.

- C9 · C10 — 래치 훅. 위 ①② 지점
- C11 — 배치 복원 상한은 S2 에서 닫혔다. S9 는 **S6 의 호출부**가 `-2` 에서 회차를
  멈추고 경보하는지를 본다
- C12 — 접두 충돌도 S2 에서 닫혔다. S9 는 **응답까지** 같은 답인지를 본다
