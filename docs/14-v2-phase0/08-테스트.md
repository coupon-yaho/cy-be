# 08 · 테스트

Phase 0 의 결함은 **두 개가 동시에 일어날 때만** 드러난다.
읽어서는 다시 못 잡으므로 테스트로 박는다.

## 기존 C1~C8 에 더한다

| # | 주입할 고장 | 방법 | 기대 |
|---|---|---|---|
| **C9** | 회수와 커밋의 인터리브 | 회수 로직을 강제 호출한 **직후** 원 요청 커밋 | 초과 발급 0. 완료 CAS 가 `-1` + `completeCasMiss` |
| **C10** | 보상된 field 에 DONE 승격 | 보상 실행 후 완료 CAS 호출 | field 가 **부활하지 않는다.** `-1` 반환 |
| **C11** | 배치 복원 상한 초과 | `stock + n > total` 이 되도록 만료 배치 주입 | `-2` + 경보. `stock` 불변 |
| **C12** | 멱등키 접두 충돌 | 같은 회원, `stored=abcdef…` 에 `request=abc` | 발급 `-4`, 보상 `0` + 기존 선점 불변 |

## C12 기대값에 주의

접두 비교를 고치는 목적은 **그 요청을 통과시키는 것이 아니다.**
같은 회원이 이미 받았으면 어차피 거절이 맞다.
목적은 **서로 다른 키를 같은 키로 오인하지 않는 것**뿐이므로 결과는 여전히 `-4` 다.

## 인터리브를 결정론적으로 만드는 법

`Thread.sleep` 으로 타이밍을 맞추면 CI 에서 깨진다. **래치를 쓴다.**

```
테스트가 제어하는 지점
  ① INSERT 직전        — 여기서 멈추고 회수 로직을 부른다
  ② 커밋 직후·완료 CAS 직전 — 여기서 멈추고 보상을 부른다
```

- 프로덕션 코드에 훅이 생긴다. **테스트 프로파일에서만 활성**되게 한다
- hot path 에 분기가 남지 않게 컴파일 타임 또는 no-op 구현으로 분리한다

## codec 단위 테스트 (01)

- 인코딩 → 디코딩 round-trip. **멱등키에 `|` 포함**한 입력
- 앞 세 필드에 `|` 를 넣으려는 시도가 인코딩에서 거부되는지
- 접두가 겹치는 두 키가 서로 다르게 판정되는지
- 값이 깨졌을 때 `-8` / `-3` 이 나오는지
- `X|1|t|k`를 Java codec과 Lua 3종이 모두 파손으로 판정하는지
- 음수 선점 시각·빈 멱등키가 값 객체 생성 시 거부되는지
- 서로 다른 기동의 생성기가 각 1,000개를 만들어도 교집합이 비어 있는지
- 멀티스레드에서 생성한 토큰에 중복이 없는지

## Lua 계약 테스트

기존 `ConsistencyRedisScriptTest` 방식을 따른다.

- 선점 → 완료 → 재시도 = `-6`
- 선점 → 보상 → 재시도 = **새 선점 성공**(field 가 지워졌으므로)
- 선점 A → 보상을 **B 의 토큰**으로 시도 = `0`, 상태 불변
- 선점 → 완료를 **B 의 토큰**으로 시도 = `-2`, 상태 불변

## 통합 확인

소규모 부하 후 **gap 4축이 전부 0** 인지. 이상 카운터 4종이 전부 0인지.

## 회귀 방어

`ConsistencyGapType.isApplicable` 이 V2 에 4축을 전부 적용하고,
`hasFinalMismatch` 에는 버전별 완화가 없다.
**FINAL 은 임계도 허용 오차도 없이 0을 요구한다** — 이 계약을 건드리지 않는다.

## S2 에 이월 — Java·Lua 교차 판정 테스트

위 "codec 단위 테스트" 중 두 줄은 S1 에서 못 닫았다. **S2 가 닫는다.**

### `X|1|t|k` 한 줄로는 아무것도 못 잡는다

Java 는 이미 이 입력을 파손으로 판정한다(`IssuedValueCodecTest`).
실제로 갈리는 건 다른 입력이다. **아래를 파라미터 테이블로 박아 Java·Lua 양쪽에 같은 입력을 먹인다.**

| 입력 | 기대 | 왜 |
|---|---|---|
| `X\|1\|t\|k` | 양쪽 파손 | 상태 문자 `[PD]` 제한 |
| `P\|1\|t\|` | **양쪽 파손** | 빈 멱등키. Lua 캡처가 `(.*)` 면 Lua 만 정상이 된다 |
| `P\|1\|t\|   ` | **양쪽 정상** | 공백만 있는 키. Java 가 `isBlank()` 면 Java 만 파손 |
| `P\|1\|t\|order-1\ntrace-2` | **양쪽 정상** | 개행은 금지 문자가 아니다. Java 가 DOTALL 없으면 Java 만 파손 |
| `P\|12345678901234\|t\|k` | **양쪽 파손** | 14자리 = 경계 바로 밖. `Long` 은 이걸 멀쩡히 파싱하므로 자릿수로 걸러야 한다 |
| `P\|9999999999999\|t\|k` | **양쪽 정상** | 13자리 = 경계 안. 상한을 너무 좁게 잡는 실수를 잡는다 |
| `P\|1\|\|k` | 양쪽 파손 | 빈 요청토큰 |

근거와 규격은 `01-값-형식.md` 하단 "S1 에서 확정한 것".
**한쪽만 통과하는 입력이 하나라도 남으면 `LUA_GAP` 이 0 으로 수렴하지 못한다.**

### 파손 → `-8`/`-3` 반환 테스트도 S1 밖이다

S1 의 codec 은 `IssuedValueCorruptException` 을 던지는 데까지다.
예외를 반환 코드로 옮기는 지점은 **S2(Lua 반환 코드)·S5(응답 매핑)** 이다.
그쪽에서 "파손 값을 넣으면 `-8`/`-3` 이 나오는지" 를 닫는다.
