# 09 · 완료 기준

아래가 전부 참일 때 Phase 0 이 끝난다. **하나라도 아니면 Phase 1 로 넘어가지 않는다.**

## 구현

- [ ] `issued` 값이 4필드 codec 이고, 앞 세 필드에 `|` 가 못 들어간다 (01)
- [ ] 요청토큰에 **인스턴스ID 가 포함**된다 (01)
- [ ] 발급 Lua 가 멱등키를 **전체 비교**하고, 완료를 첫 필드 `D` 로 판정한다 (02)
- [ ] 5종의 인자 가드가 **12 의 표와 일치**한다
- [ ] 카운터를 **쓰기 전에** 검사한다. 부분 효과가 남는 경로가 없다 (12)
- [ ] 선점 Lua 가 **인자를 쓰기 전에 검사**하고, `meta` 부분 상태를 `-9` 로 떨어뜨린다 (02)
- [ ] **완료 CAS · 보상 CAS 스크립트가 존재**하고, 무조건 `HSET`·`HDEL` 경로가 없다 (03)
- [ ] **파손 회수 경로가 존재**하고, 발급 경로가 그것을 부르지 않는다 (13 · 04)
- [ ] 회수가 **DB 대조 없이 재고를 되살리지 않고**, 상한도 본다 (13)
- [ ] 시각의 원본이 **Redis 하나**다. 호출자가 넘기는 시각이 없다 (12)
- [ ] `meta` 다섯 필드를 선점·복원이 **같이 요구**한다 (12)
- [ ] `stock` 을 못 읽는 것이 **매진으로 나가지 않는다** (02 · 06)
- [ ] 보상 호출부가 **토큰을 넘긴다.** 멱등키만 넘기는 경로가 없다 (03)
- [ ] `-4` `-6` `-7` 이 **서로 다른 응답**으로 나간다 (04)
- [ ] PENDING 처리가 **계측만** 한다. 자동 회수 코드가 없다 (05)
- [ ] 만료 배치가 **상한 검사 스크립트**를 쓴다 (06)
- [ ] 재구성·재동기화가 **동시 실행되지 않는다** (07)
- [ ] 관측 이벤트의 `engineVersion` 이 **회차별 실제 처리 엔진**이다 (11 ①)
- [ ] v2 반환 코드가 전부 고유한 `ReasonCode` 로 나간다. `UNMAPPED` 0 (11 ②)
- [ ] 정합성 리더가 v2 의 `issued` **Hash 를 읽는다** — `UNAVAILABLE` 아님 (11 ③)

## 지표

- [ ] `dupPerMember` · `replayDone` · `replayPending` 이 **분리**되어 나온다
- [ ] `stalePendingCount` · `corruptFieldCount` 가 나온다
- [ ] 이상 카운터 8종이 나온다 — `valueCorrupt` `completeCasMiss` `compensateOnDone`
      `dbUniqueViolation` `badArgument` `gateNotReady` `counterUnreadable` `stockMissing`
- [ ] 위 카운터의 음수·실패 반환을 **삼키는 경로가 없다**
