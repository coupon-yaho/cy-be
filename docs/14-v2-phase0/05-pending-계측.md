# 05 · PENDING 계측 — 자동 회수는 하지 않는다

선점하고 `DECR` 한 뒤 요청 스레드가 사라지면(GC pause, 워커 타임아웃, 프로세스 kill,
클라이언트 절단) 보상이 실행되지 않는다. field 는 `P` 로 남고 `issued_ever` 는 이미
올라갔으므로 **`PERSIST_GAP` 이 양수 = 재고 손실**이다.

이걸 주기적으로 훑어 자동 회수하려던 초안이 있었으나 **채택하지 않는다.**

## 왜 — 회수자와 원 요청이 경쟁한다

```
요청 A                          회수자
Redis 선점 (DECR)
DB INSERT 시작
                                issuances 조회 → 행 없음
                                HDEL + INCR stock + DECR issued_ever
DB COMMIT 성공
완료 CAS → 값이 없어 -1
```

회수자가 "DB 에 없다"를 확인한 시점과 A 가 커밋하는 시점 사이에
**Redis 로 관측할 수 없는 창**이 있다. 그 창에서 회수가 성사되면 DB 에는 발급이 있고
재고는 한 장 되살아난다 — 다른 회원이 그 재고를 가져가는 순간 **I1 초과 발급**이다.

`staleAfter` 를 늘려도 해결되지 않는다. GC pause · DB stall · 커밋 응답 유실은
어떤 값이든 넘길 수 있어 **확률만 낮아진다.**

03 의 완료 CAS 가 "지워진 field 의 부활"은 막는다. 그러나 **회수가 이미 `stock` 을
늘린 뒤라면 늦었다.**

## 그래서 세기만 한다

```
주기(예: 30초)마다 OPEN 회차마다
  HSCAN cy:v2:issued:{r} COUNT 200      ← 커서 방식. 한 번에 200필드씩만
    상태가 P 이고 나이 > staleAfter 인 field 수를 센다
      → stalePendingCount 게이지로 노출. 값을 건드리지 않는다
```

- 상태 판정은 codec 으로만 한다. **파손 값은 `P` 도 `D` 도 아니다** — `stalePendingCount`
  에 섞지 말고 `corruptFieldCount` 로 따로 센다. 섞으면 재구성으로도 안 풀리는 자리를
  "곧 만료될 선점" 으로 오인한다(13 의 파손 회수 대상이 이 게이지다)
- `HSCAN` 은 커서 방식이라 O(N) 금지(§3.3)에 걸리지 않는다
- hot key 를 만지므로 `COUNT` 로 쪼개고 **부하 중에는 주기를 늘린다**
- `staleAfter` 는 이제 회수 판정이 아니라 **집계 기준**이라 짧아도 위험하지 않다
- api 가 여러 대면 **대당 한 번씩 돌아 부하가 N 배**다. batch 로 옮기거나 리더 선출을 둔다

## 실제 회수는 두 곳뿐이다

| 회수 지점 | 왜 안전한가 |
|---|---|
| `-7` 재시도의 자가 치유 | 원 실행과 겹쳐도 **`uk_coupon_member` 가 중복 INSERT 를 튕긴다**(§4.6) |
| 재구성 · 재동기화 | `meta` 를 지워 **발급이 멈춘 상태**에서 돈다 |

## 그럼 고아 선점은 언제 풀리나

**TTL 도 두지 않는다.** TTL 은 Hash field 단위로 못 걸고, 걸 수 있어도 위의 경쟁을
"시간이 정한다" 로 바꿀 뿐이다. 회수 경로는 아래 둘이 전부이고 **둘 다 발급이 멈춘 상태**다.

| 경로 | 언제 |
|---|---|
| `-7` 재시도의 자가 치유 | 클라이언트가 다시 온다. `uk_coupon_member` 가 중복 INSERT 를 튕긴다 |
| 재구성 · 재동기화(07) | 운영이 돌린다. 게이트가 닫혀 있다 |

`stalePendingCount` 가 임계를 넘으면 **재동기화를 태우는 것이 대응**이지, 스위퍼를 켜는 것이
아니다. 그 판단을 사람이 하도록 남긴 것이 이 문서의 결론이다.

## 맞바꾼 것

죽은 선점의 재고가 **캠페인 종료까지 묶인다.** 과소 방향이라 불변식은 깨지지 않고,
`stalePendingCount` 와 `PERSIST_GAP` 이 그 양을 그대로 보여준다.

> **되돌릴 수 없는 초과 발급 위험을, 되돌릴 수 있는 과소 재고와 맞바꾼 것이다.**

## S7 인계

- 계측은 `P` 의 **나이**만 본다. 완료 CAS 는 선점시각을 **보존하므로**(03) `D` 의 나이도
  이제 의미가 있다 — 다만 그건 "선점된 지 얼마" 이지 "완료된 지 얼마" 가 아니다.
  `D` 를 stale 로 세지 않는다.
- 게이지는 두 개다 — `stalePendingCount` · `corruptFieldCount`. 둘 다 회수 트리거가
  아니라 **재동기화 판단의 입력**이다. batch 가 값을 건드리는 코드는 넣지 않는다.
- **`HSCAN` 은 같은 field 를 두 번 돌려줄 수 있다.** 순회 도중 Hash 가 커져 rehash 되면
  그렇다. 그래서 부하가 도는 동안의 두 건수는 **과다 방향으로 틀릴 수 있다.** field 를
  모아 두면 정확해지지만 회차당 수백만 개라 batch 힙을 그만큼 먹는다 — 정확도를 사는
  값으로 비싸다. 게이트가 보는 시점에는 Hash 가 자라지 않아 중복이 나지 않고, 과다
  방향은 FINAL 을 **막는** 쪽이라 안전하다. 부하 중 수치는 추세로만 읽는다.

  ⚠️ 그 "자라지 않는다" 를 받쳐 주는 것은 **`LOAD_STOPPED` 가 아니다.** 그 전이는
  run_status 를 옮길 뿐 진행 중인 요청을 drain 하지 않아, 늦게 도착한 V2 발급이
  계속 `HSETNX` 로 field 를 붙인다. Redis 는 순회 중 **추가된** 원소의 반환을
  보장하지 않으므로, 그 구간의 스캔은 `VALID + 0` 으로 FINAL 을 잘못 열 수 있다.
  받쳐 주는 것은 게이트 ①②(정적 구간 5초 이상 · 인플라이트 0)다(12 문서). 게이트를
  `LOAD_STOPPED` 만으로 구현하면 이 전제가 사라진다.
- 정합성 리더의 `HLEN` 에는 파손 field 도 잡힌다. `corruptFieldCount` 가 0이 아니면
  `LUA_GAP` 의 일부는 발급 누락이 아니라 파손이다 — **해석의 입력**이다(11 ③).

## FINAL 진입 게이트가 바뀐다

기존 ④ "PENDING 스위퍼가 1회 완주" → **`stalePendingCount` 와 `corruptFieldCount` 가 0**.
0이 아니면 재동기화를 한 번 태운 뒤 FINAL 을 구한다.

### 수집이 멈춘 것과 한 바퀴가 긴 것을 가른다

노후 판정은 시간에 기대므로, 수집이 멈추면 **마지막 스캔에서 임계 전이던 PENDING 이
그 뒤 노후화돼도 게이지는 `VALID + 0`** 이다. 게이트가 그걸 통과로 읽는다. 그래서
회차 나이가 아니라 **사이클이 다시 돌았는지**로 판정한다.

반대로 회차가 늘거나 Hash 가 커져 한 바퀴가 길어지는 것은 장애가 아니다. 허용치를
직전 바퀴 길이로 잡되, **바퀴가 도는 동안에는 재지 않는다** — 허용치는 과거 바퀴로
계산한 값이라, 부하가 실려 이번 바퀴가 갑자기 길어지면 방금 읽은 회차까지 뒤집는다.

남는 구멍 하나: 바퀴가 **끝나지 않는** 경우(스캔이 무기한 붙들림)는 마지막 값이
유지된다. 명령 타임아웃이 바퀴를 끝내 주는 것에 기대고 있다.

### 게이트는 "0" 과 "판정 불가" 를 갈라야 한다

이 게이트는 게이지 **값**만 보면 안 된다. 수집기는 못 읽은 것을 0 으로 적지 않고
`NaN` + `state=UNAVAILABLE` 로 적는다 — 못 읽은 회차를 0 으로 적으면 게이트가
"고아 PENDING 이 없다" 로 읽고 그대로 FINAL 을 준다. 그래서 게이트 조건은
`값이 0` 이 아니라 **`state 가 VALID 이면서 값이 0`** 이다.

시계열이 **아예 없는** 경우도 같은 자리다. 회차별 게이지는 등록에 실패하면
반쪽으로 남지 않도록 되감아 지우므로(`PendingIssuedGaugeCollector#register`),
그 회차는 `state` 조차 없다. `absent()` 를 따로 걸지 않으면 게이트 식이
아무 행도 만나지 못하고, 대부분의 구현은 그것을 통과로 읽는다.

- 게이트 식에 `absent(...)` 절을 함께 건다.
- 등록 실패 자체는 회차 태그 없는 카운터로 따로 노출한다 — 회차 태그를 달면
  등록 실패의 원인(카디널리티)을 그대로 재현한다.

표준 Micrometer 의 미터 상한은 DENY 로 Noop 을 돌려주지 예외를 던지지 않아
현재 구성에서는 발현되지 않는다. 게이트 쪽 작업이라 계측 PR 밖에 둔다.
