# 12 · 인자 가드 · 시각 · meta 계약

Lua 5종이 **공유하는 입력 규약**이다. 02·03·06 의 스크립트 본문은 여기 규약을 따른다.

> 값 형식 자체는 `01`, 각 스크립트의 흐름은 `02`(선점) · `03`(완료·보상) ·
> `06`(배치 복원) · `13`(파손 회수) 에 있다.

## 어느 스크립트가 무엇을 보는가

| 인자 | 선점 | 완료 | 보상 | 회수 | 복원 |
|---|---|---|---|---|---|
| **인자 개수 부족** | `-10` | `-10` | `-10` | `-10` | `-3` |
| `memberId` 빈 값 | `-10` | `-10` | `-10` | `-10` | — |
| 멱등키 빈 값 | `-10` | — | — | — | — |
| 요청토큰 빈 값 · `\|` 포함 | `-10` | `-10` | `-10` | — | — |
| 등급 비트 비숫자 · 32비트 초과 | `-10` | — | — | — | — |
| 복원여부 플래그 | — | — | — | `-10` | — |
| 총재고 비숫자 | — | — | — | `-10` | — |
| 건수 비숫자 · 0 이하 · 비정수 | — | — | — | — | `-3` |

**복원만 `-3` 인 것은 06 의 반환표가 먼저 그렇게 정했기 때문**이고, 뜻은 같다.
호출부는 숫자가 아니라 `IssuanceScriptCodes` 를 본다.

## 인자를 먼저 본다 — 쓰기 경로가 읽기 경로를 파손시킬 수 있다

빈 멱등키를 그대로 이으면 `P|now|token|` 을 쓰고 **자기 파서가 그 값을 파손으로 거부한다.**
토큰에 `|` 가 섞이면(`instanceId="api|1"`) 필드 경계가 밀려 03 의 토큰 CAS 가 **잘못 잘린
문자열을 비교**한다 — 보상이 남의 선점을 되돌리는 초과 발급 방향이다.

codec 의 인코딩 검증은 Java 경로에만 있고 **Lua 는 codec 을 거치지 않으므로**, 가드는
스크립트 안 · 어떤 쓰기보다도 앞이어야 한다.

**`memberId` 는 다섯 중 넷이 본다.** 선점에서는 빈 값끼리 같은 field 를 공유하고,
완료·보상·회수에서는 더 나쁘다 — `HGET` 이 `false` 라 **보상이 `0`(내 것이 아님 = 정상)을
돌려준다.** 삼켜지는 실패라 카운터도 안 오르는데 선점 때 깎인 재고는 잠긴다.
저장된 값과 같아질 수 없는 인자는 **비교가 아니라 버그**라는 규칙이 여기도 그대로다.

**인자 개수부터 본다.** 어댑터가 하나를 빠뜨리면 `ARGV[n]` 접근이 Lua 런타임 에러가 되고,
호출부는 그것을 `RedisSystemException` — 즉 **"Redis 장애"로 오진**한다. 06 의 "Redis 실패는
전파하지 않는다" 와 만나면 그대로 삼켜진다.

**등급 비트도 본다.** `bit.band` 는 `nil` 이면 런타임 에러(정체불명 5xx)고, 소수·음수는
조용히 절삭돼 **등급 판정이 어긋난다.** 게다가 32비트 연산이라 `2^32+1` 이 최하위 비트로
접혀 마스크와 겹치므로 **상한도 같이 본다.**

**`meta` 의 `gradeMask` 도 같은 연산에 들어간다.** 인자만 보고 마스크를 안 보면
`gradeMask = -1` 일 때 `bit.band(-1, x) == x` 라 **전 등급이 통과한다.** 초과 발급
방향이라 `-9` 로 막는다 — 인자가 아니라 게이트 데이터가 이상한 것이므로 `-10` 이 아니다.

**저장된 토큰은 `([^|]+)` 라 빈 값이나 `|` 가 든 값과 같아질 수 없다.** 그런 인자를
그냥 비교하면 보상은 언제나 `0`(내 것이 아님 = 정상)을 돌려준다 — **삼켜지는 실패**라
카운터도 안 오르는데 선점 때 깎인 재고는 잠긴다. 완료는 `-2` 로 나가 경보는 뜨지만
원인이 "경합" 으로 오진된다. 그래서 **비교가 아니라 버그로 다룬다.**

## 카운터는 Redis 의 계약으로 본다

`stock`·`issued_ever` 는 `DECR`·`INCR` 대상이라 **canonical 정수 문자열**이어야 한다.
Lua 의 `tonumber` 기준으로 보면 안 된다 — `'1e1'` 은 Lua 로는 정수 10이지만
**`DECR` 은 그 값을 거부**한다.

**판정 집합은 Redis 의 `string2ll` 보다 일부러 좁다.** 형식은 같고(`0` 또는 `-?[1-9]%d*`)
**자릿수를 15로 묶는다.**

```lua
local function isCanonicalInt(s, signed)
    if s == false or type(s) == 'table' or #s > 15 then return false end
    if s == '0' then return true end
    if signed then return string.match(s, '^-?[1-9]%d*$') ~= nil end
    return string.match(s, '^[1-9]%d*$') ~= nil
end
```

```
쓰기 전에 본다      GET stock · GET issued_ever  →  isCanonicalInt(_, true)
통과 못 하면        -11 (선점은 방금 만든 field 를 되돌린다)
키 부재             issued_ever 는 예열이라 정상. stock 은 -11
```

**양쪽으로 실패 모드가 있다.**

```
넓으면        '007' · '-0' 이 통과하고 DECR 이 거부해 쓰기가 중간에서 터진다
너무 넓어도   상한 검사가 조용히 무력화된다
```

`tonumber` 도 `'^-?%d+$'` 도 `'007'`·`'-0'` 을 통과시키는데 **`DECR` 은 거부한다**
(`ERR value is not an integer or out of range`). Lua 는 원자적이어도 이미 적용된 쓰기를
되돌리지 않으므로 짝 없는 `P` 가 남는다.

반대로 int64 전체를 받으면 **`left + n > total` 이 조용히 틀린다.** Lua 5.1 의 수는
double 이라 2^53 위에서는 `a + 1 > a` 가 `false` 다(실측:
`tonumber('9223372036854775807')` → `9.2233720368548e+18`, `a + 1 > a` → `false`).
**15자리는 2^53(≈9.0e15) 아래라 정수 연산이 정확하다.** 재고·누적 발급수가 10^15 를
넘을 일이 없으므로 **넓히지 않는다.**

**허용 집합은 연산에 대해 닫혀 있어야 한다.** 15자리 `999999999999999` 를 "정상" 으로
통과시키면 `INCR` 이 16자리를 만들고, **그 값을 다음 호출의 같은 가드가 파손으로 막는다** —
우리가 쓴 값을 우리가 못 읽는 상태다. 그래서 선점은 `issued_ever` 가 그 경계값이면
**쓰기 전에** `-11` 로 거절한다. `stock` 의 `DECR` 은 값이 0 쪽으로 줄어들어 해당 없고,
회수·복원의 `INCR` 은 총재고 상한이 막는다.

그래서 5종이 같은 함수 하나를 쓴다.

**이 검사가 늦으면 부분 효과가 남는다.** Lua 스크립트는 원자적이지만 **이미 적용된 쓰기를
되돌리지 않는다.** `HSETNX` 뒤에서 `DECR` 이 터지면 짝 없는 `P` 가 남고, 그 값은 형식이
멀쩡해서 파손 회수(13)도 `-1` 로 거부한다. `DECR` 은 되고 `INCR issued_ever` 만 터지면
`stock` 만 줄어 **`PERSIST_GAP` 이 어긋난다.**

보상·회수도 같다 — `HDEL` 과 `INCR` 만 적용된 채 `DECR` 이 터지는 순서라 **되돌리기 전에**
본다.

## `meta` 값도 같은 기준이다

`totalQuantity`·회수의 총재고 인자·복원의 건수도 같은 `isCanonicalInt` 를 지난다.
`tonumber` 만 보면 `'1e9'`·`'10.0'`·`'007'` 이 통과한다.
**숫자값이 맞다면 상한 계산도 맞으므로 이 가드가 막는 것은 초과 발급이 아니다** —
막는 것은 **작성자가 우리가 기대한 경로가 아니라는 사실**이다. `double` 을 거쳐 `'1.0E9'` 가
들어오면 지금은 조용히 통과하고, 그 뒤 누가 그 문자열을 다시 쓰면 그때 깨진다.
`^%d+$` 를 요구해 **S8 의 작성 계약을 스크립트가 강제**한다(어기면 `-1`/`-9`).

값 자체가 틀린 경우(진짜 총재고가 10인데 10억이 적힌 경우)는 형식 가드로 못 잡는다.
그건 `DB_COUNTER_GAP` 의 몫이다.

## 시각의 원본은 Redis 하나다

`nowMillis` 를 **인자로 받지 않는다.** api 가 여러 대라 호출 인스턴스의 시계를 믿으면
마감 경계에서 인스턴스마다 다른 답이 나가고, 시계가 앞선 인스턴스가 남긴 선점은
**나이가 음수**라 `stalePendingCount` 가 영원히 못 잡는다 — 05 의 FINAL 게이트가
못 보는 자리가 생긴다.

```lua
local clock = redis.call('TIME')
local now = tonumber(clock[1]) * 1000 + math.floor(tonumber(clock[2]) / 1000)
```

**값에 쓸 때는 `string.format` 을 거친다.** Lua 5.1 의 숫자는 double 이라
`1700000000000` 을 그냥 이으면 `1.7e+12` 가 된다 — 자기 파서가 파손이라 부를 값이다.
`'%d%03d'` 로 초와 밀리초를 따로 찍어 **자릿수 문제 자체를 없앤다.**

`TIME` 은 비결정적 명령이라 스크립트가 effect replication 에 기댄다. Redis 7 의 기본값이
그것이므로 지금 배포에서는 제약이 아니다.

## meta 는 부분 상태일 수 있다

재구성은 `meta` 를 지우고 마지막에 다시 쓴다(07). 그 창의 `HMGET` 은 일부 필드만 돌려줄 수 있고,
`status` 하나만 보고 넘기면 `tonumber(nil)` 비교에서 **Lua 런타임 에러**가 난다 — 클라이언트는
`503 + Retry-After` 대신 정체불명의 5xx 를 받는다.
**빈 문자열도 존재로 친다** — Lua 에서 `''` 는 truthy 라 `not meta[1]` 을 그냥 통과하고,
그다음 `~= 'OPEN'` 에 걸려 **미준비가 마감(`-1`)으로 둔갑한다.** 나머지 세 필드는
`tonumber` 가 2차 방어를 하지만 `status` 에는 그게 없다.
**다섯 필드의 존재와 숫자 변환을 모두 확인하고, 하나라도 아니면 `-9` 다.**

`totalQuantity` 는 선점이 쓰지 않는다. 그래도 **같이 요구한다** — 06 의 배치 복원이 그걸
읽기 때문이다. 네 필드만 보고 게이트를 열면 **발급은 도는데 만료 복원만 영구히 죽는**
조합이 만들어지고, 그 상태는 `-1`(미준비)로만 나타나 아무도 원인을 못 찾는다.
`meta` 의 필드 계약은 스크립트마다 다르면 안 된다.

## `totalQuantity` 를 선점도 요구한다

선점은 그 값을 쓰지 않는다. 그래도 다섯 필드를 다 요구한다 — **복원(06)이 그것을 읽기 때문**이다.
네 필드만 보고 게이트를 열면 **발급은 도는데 만료 복원만 영구히 죽는** 조합이 만들어지고,
그 상태는 복원의 `-1`(미준비)로만 나타나 아무도 원인을 못 찾는다.

**`meta` 의 필드 계약은 스크립트마다 다르면 안 된다.** 재구성(07)은 다섯을 한 번에 쓴다.

## S3 인계 — 어댑터가 닫을 것

- 스크립트 상수는 `infra/redis` 의 `IssuanceScripts` 에 있고 **반환 코드는
  `IssuanceScriptCodes` 뿐이다.** 어댑터·응답 매핑에 숫자 리터럴을 다시 쓰지 않는다.
- **키 이름과 해시태그 `{r}` 의 출처는 어댑터 한 곳이다.** 지금은 S2 계약 테스트에만
  리터럴로 있다 — 베끼지 말고 어댑터가 소유한 뒤 테스트가 그 쪽을 쓰게 한다.
- 선점 반환은 **실패면 1원소, 성공이면 2원소**다. `List` 원시 타입에는 그게 안 드러난다 —
  값 객체(코드 + 잔여 재고)로 가두고 `get(1)` 을 어댑터 밖으로 내보내지 않는다.

## S3 에서 확정한 것 — 어댑터가 닫은 부채 두 개

### ① `stock`·`issued_ever` 자료형 오류는 `pcall` 로 감싼다(현행 유지)

선점은 **`HSETNX` 로 field 를 만든 뒤에** 카운터를 읽는다. `GET` 이 `WRONGTYPE` 으로 터지면
스크립트가 그 자리에서 중단되고 **`DECR` 없는 고아 `P`** 가 남는다. 그 값은 형식이 멀쩡해서
파손 회수(13)도 `-1` 로 거부하고, 그 회원은 영구히 `-7` 이다.

`pcall` 이면 에러 테이블이 `isCanonicalInt` 의 `type(s) == 'table'` 에 걸려 `-11` + `HDEL`
롤백으로 나간다. 어댑터는 이것을 `RedisSystemException`(= "Redis 장애" 오진)이 아니라
`COUNTER_UNREADABLE` 로 옮긴다 — **Lua 본문 변경은 없다.**

`meta` 쪽 `HMGET` 은 계속 감싸지 않는다. 그건 쓰기 전이라 터져도 상태가 안 남는다.

### ② KEYS 순서는 통일하지 않고 타입으로 가둔다

`issued_ever` 는 선점에서 `KEYS[4]`, 보상·회수에서 `KEYS[3]` 이다. 순서를 통일하면 Lua 5종
본문과 이 문서의 표, S2 계약 테스트가 함께 흔들린다 — **S2 재작업**이고 설계 §0.1 이 구조
변경을 반려한 상태라 S3 의 판단 범위 밖이다.

대신 `IssuanceScriptRunner` 가 **스크립트마다 하나씩인 진입점**을 갖고 키 리스트를 자기가
만든다. 호출부는 회차와 ARGV 만 넘기므로 순서를 틀릴 자리가 없다 — 계약 테스트도 이 통로를
쓴다. ARGV 를 `Object...` 로 둔 것은 **모자란 인자와 빈 문자열까지가 계약**이기 때문이다.

### 키와 `meta` field 이름의 출처

- 키 네 개는 `IssuanceKeys` 하나가 만든다. 해시태그 `{회차}` 를 붙일 다른 길이 없다.
- `meta` 의 다섯 field 이름은 `RedisIssuanceGate` 가 소유하고, 쓰기는 `HSET` **한 번**이다.
  `GateMeta` 가 다섯을 한 덩어리로 묶어 부분 쓰기 자체를 불가능하게 한다.
- 관측 설정에서 v2 키를 줄 때는 `cy:v2:stock:{{couponId}}` 처럼 **해시태그 안에**
  자리표시자를 넣는다(`DomainGaugeProperties`).
- 11 ③(정합성 리더의 Hash 분기)은 이 단위에서 같이 닫았다. 표본 자료형이 `hash` 였던 기존
  테스트는 `stream` 으로 바꿨다 — hash 는 이제 지원 자료형이다.

### 선점 반환

`ClaimResult` 로 가둔다. 거절에는 잔여 재고가 **없고**, 꺼내려 하면 예외다 — 0 으로 채우면
"매진" 과 구분되지 않는다. `get(1)` 은 어댑터 밖으로 나가지 않는다.

### S3 이 닫지 않고 넘긴 것 — S8·S4 인계

| 받는 단위 | 내용 |
