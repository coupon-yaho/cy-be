# 관측 전용 계정이 SELECT 할 수 있는 테이블의 **정본**이다.
#
# 이 파일 하나를 세 곳이 읽는다:
#   1. infra/mysql/obs-grants/apply.sh        — 실제 GRANT 를 만든다
#   2. compose.yml 의 obs-grants 일회성 서비스 — 위 스크립트를 컨테이너 안에서 돌린다
#   3. ObservationAccountPrivilegeTest        — 이 목록과 실제 질의문이 어긋나면 깨진다
#
# 목록에 없는 테이블은 obs 계정이 읽지 못한다(MySQL 1142). 그것이 이 파일의 목적이다 —
# 특히 members 는 여기 없어야 한다. 개인정보 컬럼은 암호화돼 있지만 HMAC 블라인드
# 인덱스(email_hash · phone_hash)로 동일인 대조가 되고, membership_grade · created_at 은
# 평문이다.
#
# ⚠️ 줄을 추가하기 전에 물을 것 — 관측 경로가 **이미** 그 테이블을 읽고 있는가?
#    "나중에 쓸 것 같아서" 미리 넣으면 이 파일은 양성 목록이 아니라 두 번째 스키마 GRANT 가
#    된다. 읽는 코드가 먼저 들어오면 ObservationAccountPrivilegeTest 가 그 자리에서
#    "목록에 없는 테이블을 관측 풀로 읽는다" 며 깨져서, 추가를 강제한다.
#
# 형식: 한 줄에 테이블 하나. # 로 시작하는 줄과 빈 줄은 무시한다.
#       이름은 영숫자·밑줄만 허용한다(apply.sh 가 검사한다).

# ── Spring Batch 메타. 우리가 만든 것이 아니라 프레임워크가 만든다 ──
#    관리자 배치 이력 화면이 읽는다(JdbcBatchExecutionRepository).
#
#    BATCH_STEP_EXECUTION 은 "어떻게 돌았나" 를 지고 있다 — 읽기/쓰기/스킵/롤백 카운터가
#    거기 있고, 잡 수준 표는 "돌았다/안 돌았다" 까지만 답한다(CY-910).
#    실패 원문(EXIT_MESSAGE)도 이 표에 있지만 그대로 내보내지 않는다 — FailureSummary 가
#    도메인 에러코드나 예외 이름까지만 남긴다.
#
#    BATCH_JOB_EXECUTION_PARAMS 는 "무슨 조건으로 돌았나" 를 진다 — 실패한 실행을
#    재현하는 시작점이고, IDENTIFYING 이 "같은 조건으로 또 돌린 것" 을 가른다(CY-911).
BATCH_JOB_EXECUTION
